### What the inline block is

- `public/player-critical.css`, generated by `scripts/player/critical-css.mjs` from the built (esbuild-minified) player.css, printed by
  `src/lib/player/critical-css.ts` as `<style id="scp-critical">` at the top of every embedded fragment (hub and tab addresses), before
  `#scp-host-header`. The app's own standalone pages, which load player.css render-blocking, do not get it.
- **Size: 46,977 bytes in the fragment (9.4 KB gzipped), 395 rules.** It is that big because the header is: 572 of player.css's rules
  sit in `@container pp (...)` queries and the phone header alone is ~12 KB of them; ~300 custom properties of the root's team palette
  were pruned to the ones the header uses (the block was 20 KB of variables before pruning).
- **Selection, never hand-copied:** every rule of player.css whose selector matches the root, the search box, the header or the tab strip
  (or anything inside them) on real fragments (8 players' hubs: RB, rookie TE on IR, QB, WR, TE, K, a long name, a 2-game backup;
  plus two tab addresses; plus the first two hubs in their booted state: tabs owned by the script, search shown, photo well
  `is-missing`), tested with jsdom. Rules keep player.css order. A selector that also matches something outside the header
  (`.scp *`, `.scp a`: 8 of them) gets `:where(<header scope>)` on its subject: zero added specificity, and it cannot reorder anything
  in the body. Because the block holds every rule that can touch a header element, in order, the header's cascade when player.css
  lands is the same rules applied again: nothing moves.
- **Drift test** (`tests/player-critical-css.test.mjs`, 5 tests): (1) the committed file equals what the generator produces from
  today's player.css and today's fragments (checked to fail: changing the phone header's `margin: 8px -8px 0` to 9px in player.css
  fails it and test 2); (2) every inline rule exists in player.css with the same declarations, in player.css order; (3) player.css
  opens the panel gate; (4) the container queries are present and the block stays under 60 KB; (5) the fragment prints it once,
  first, on hub and tab addresses, and the standalone page does not. Regenerate with `node scripts/player/critical-css.mjs`
  (boots the built server itself; ~40 s) after any player.css or header markup change.

### The panel gate (the one hand-written part, 305 bytes at the end of the block)

The header alone was not enough: the first after runs (header inline, panels not) measured CLS 0.42-0.60 on 3 of 6 runs, all from
the body: the Overview below the tab strip painted with Rocket's critical CSS (giant unsized SVG icons, unstyled sections) and
reflowed when player.css landed, pushing Divi's footer out of the first screen. So until player.css has arrived:

    :where([data-scp-root]){min-height:var(--scp-sheet-min,100vh)}
    :where([data-scp-root])>:where(:not(.scp-search,.scp-phead,.scp-controls,script,style)){visibility:var(--scp-sheet-vis,hidden);overflow-x:var(--scp-sheet-ovx,clip);animation:scp-sheet 0s 4s forwards}
    @keyframes scp-sheet{to{visibility:visible}}

and player.css opens it with `.scp[data-scp-root]{--scp-sheet-vis:visible;--scp-sheet-ovx:visible;--scp-sheet-min:0px}` (new rule
near the top of player.css). The panels are laid out but not painted, cannot widen the page, and the root is at least one screen
tall so the host footer cannot sit in the first screen and then be pushed out. Zero specificity: any player.css rule wins. If
player.css never arrives (asset host down, blocked request) the panels are shown, unstyled, after 4 s rather than never. The
reservation exists only before player.css (final root min-height 0); the final layout reserves nothing. While hidden, panel content
is not focusable or readable by assistive technology; the header, search and tab strip are.

### Rocket's critical CSS: why it painted the header wrong, and why it no longer matters

Rocket's inline critical CSS for the player template has **zero `@container` rules** (its generator drops them), and the phone
header layout lives entirely in `@container pp (max-width: 560px)` etc. That, more than staleness, is why the header painted as a
squeezed desktop grid. The inline block is printed in the body, after Rocket's `<style id="rocket-critical-css">` in `<head>`, so
at equal specificity ours wins; it carries the container queries. Rocket's rules that outrank ours (higher specificity or
`!important`) also outrank player.css, so they are the same before and after player.css lands and cannot cause a shift. One of
them did move things: the stale `!important` 8px margin rule (round 1), still neutralized by `#scp-host-header`. Rocket's critical
CSS still applies to player pages (not removed): removing it would need a WP Rocket setting or filter per page, and it is harmless now.

Verification (`critverify.mjs`, production shell, real Divi + Rocket critical CSS + fonts): with player.css **blocked**, every
element of the search box, header and tab strip (147 on Gibbs, 103 on Large) has the same box as with player.css at 320, 390, 768
and 1280, and the first panel starts at the same y (Gibbs 444.5 / 440 / 699.5 / 506.5; Large 325 / 339 / 604.5 / 506.5). No
horizontal overflow in the critical-only state at any width. Screenshots: `final4/crit-<player>-<width>-{critical-only,full}.png`
(the critical-only shots are taken after 6 s, so they show the 4 s fallback revealing the unstyled panels).

## Round 1: cause and the render-blocking variant (superseded by round 2 where they differ)

### Round 1 summary

- **Cause of the phone CLS (measured, production):** WP Rocket's "Load CSS asynchronously" rewrites `news.statchasers.com/player.css` into `<link rel=preload ... onload="this.rel='stylesheet'">`. Until it applies, the player header is laid out by Rocket's inline critical CSS for the template, which carries the desktop three-column hero grid (`minmax(220px,20%) minmax(0,1fr) minmax(300px,27%)`) and not the phone override. At 390px that squeezes `.scp-pid` (name, tags, spec) to a **0px column** and makes the hero 930-1,010px tall. When player.css lands the hero collapses to 162-263px and everything under it moves up: `.scp-pid`, `.scp-pp-cards`, the tab strip and `section#overview` are the shifted nodes. **0.18 on the Gibbs hub, 0.68-0.70 on a thin profile, every load measured on production today.**
- **Second, small shift (0.008, every phone load):** the same critical CSS is stale: it still has `.scp.scp.is-embed>.scp-search[hidden]+.scp-phead{margin-top:0!important}`, which player.css dropped on 11-20. Inline in `<head>` it outlives player.css, so the header sits 8px high until the player script reveals the search box, then the page drops 8px.
- **Fix:** player.css and the player bundle load from the WordPress origin with the WEB-023 local-asset pattern, excluded from Rocket's async rewrite, so the header paints once, in its final layout; the asset-host fallback is excluded from the async rewrite too. The fragment's inline `#scp-host-header` style restates the 8px phone margin over the stale critical rule.
- **Result (production shell, 3 runs each, same conditions):** CLS 0 on every run for both players (worst 0.002 counting emulation-flagged shifts). TBT median Gibbs 689 -> 327 ms, Large 170 -> 117 ms. **Cost: first paint is later** (FCP median 688 -> 1,668 ms Gibbs, 572 -> 1,668 ms Large under slow 4G), because the page now waits for player.css; Gibbs LCP is unchanged (2,068 -> 2,060), Large LCP 824 -> 2,000 ms because its "before" LCP was the giant jersey number painted in the broken state. A decision for mak (see Open).
- **Duplicates:** no table, card or FAQ is printed twice for desktop and mobile on the hub or any tab. The header has phone and desktop variants of its identity lines and start/sit link (about 23 phone-only elements); left as they are (reasons below). DOM unchanged by this branch: Gibbs 5,066 elements live (6,589 before the 11-26 trim, so that trim is live), Large 870.
