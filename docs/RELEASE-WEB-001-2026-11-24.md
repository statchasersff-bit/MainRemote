### Plugin 1.10.61, against the live 1.10.60

Only `statchasers-matchup.php`, `readme.txt` and the two version lines differ from the live zip. Every other file is byte-identical.

1. A numbered playoff round 301s to its named address: `/2025-postseason-week-5/` goes to `/2025-super-bowl/`.
2. A game with `modified: null` gets no `<lastmod>` in the game sitemap, and the sitemap index entry gets none either. 1.10.60 printed the kickoff date.
3. When the game list changes, the plugin clears Rank Math's cached **sitemap index** as well as the game files. Without this, the cached index kept listing 2 pages with their old lastmods after the list grew to 8 pages.
4. A game segment the validator refuses (`/2026-week-30/`, `/2026-week-02/`) is a 404 with **noindex and no canonical**. It used to print `index` and the pair's canonical. The live site does this today.

### API changes (WEB-001)

- Every completed game is canonical at its own dated URL.
- The game sitemap lists all 1,586 completed games from 2021-2026, with `modified: null`.
- Schedule, hub and player links point to the dated page.

## Rollout order: ZIP first, then API

Rehearsed on a local WordPress 6 + Rank Math 1.0.282 + MariaDB 10.5 site.
- It started from the production state: plugin 1.10.60, API `b1f6ad5`, and Rank Math's cache primed.
- It was then upgraded the way production is.
- The output of `scripts/web001-release-check.sh` matched the public site line for line in the start state.

| State | Sitemap | Week 11 canonical | Alias | `/2026-week-30/` |
|---|---|---|---|---|
| Production today (1.10.60 + `b1f6ad5`) | 2 pages, 298 URLs, all with lastmod | pair URL | 200, self-canonical duplicate | 404, `index`, pair canonical |
| **Step 1:** ZIP 1.10.61 + `b1f6ad5` | unchanged (298, lastmod from the old API) | pair URL (old API) | **301 to /2025-super-bowl/** | **404 noindex, no canonical** |

Step 1 is safe on its own. It only adds the two plugin fixes. The wrong order publishes 1,586 false lastmods until the zip lands, so the zip goes first.

### Steps

Do these in the release window (14:00-16:00 UTC), outside game windows. Thursday 2026-11-26 is Thanksgiving, with games from about 17:30 UTC.

0. **Before.** Record the baseline:
   ```
   scripts/web001-release-check.sh > web001-before.txt
   ```
   Back up the live plugin:
   ```
   cp -a ~/public_html/wp-content/plugins/statchasers-news ~/tmp/statchasers-news-1.10.60-backup-<date>
   ```
1. **Plugin.**
   - Upload the zip and confirm `sha256sum` = `8ad987d4...`.
   - Install it:
     ```
     wp plugin install ~/tmp/statchasers-news.zip --force
     wp eval 'statchasers_news_run_upgrade_now();'
     ```
     The second command should print `true`.
   - The version change runs 1.10.60's single-claim sweep. It clears the cached player and team renders (about 1,550 rows), so those pages render cold until the warm in step 5.
   - Check:
     ```
     BUST=1 scripts/web001-release-check.sh
     ```
     Expect `Stable tag: 1.10.61`, the alias as a 301, and week-30 as noindex. Everything else is unchanged.
2. **API.**
   - Replit Publish from `release/web-001-2026-11-24`.
   - Wait for `https://news.statchasers.com/api/status` to report the release commit in `datasets.build.commit`.
3. **Refresh the game list now.** Otherwise Rank Math serves its cached index until some post is saved:
   ```
   wp eval 'delete_transient("sc_matchup_games"); delete_transient("sc_matchup_games_fail"); echo count(statchasers_matchup_games());'
   ```
   Expect `1586` or more as more games finish. This clears Rank Math's game files and its index.
4. **Wait 5 minutes** for the plugin's matchup fragment cache. Then:
   ```
   BUST=1 scripts/web001-release-check.sh > web001-after-busted.txt
   ```
   This must match the Step 2 row above.
5. **Purge (needs approval):**
   ```
   cd artifacts/api-server && nohup pnpm purge-and-warm > ~/purge-and-warm.log 2>&1 &
   ```
   This follows docs/RELEASE-WINDOW.md step 8.
6. **After the purge:**
   ```
   scripts/web001-release-check.sh > web001-after.txt
   ```
   - Run it without BUST, so it reads the public cached copies.
   - Run it once more with a desktop UA (`UA='Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/124'`).
   - Both runs must match the Step 2 row.
   - Then submit `/sitemap_index.xml` in Search Console.

## Rollback (reverse order: API first, then plugin)

1. **API.**
   - Redeploy the previous Replit deployment (`b1f6ad5`).
   - Run step 3 again. Expect `298`: the sitemap returns to 2 pages and canonicals go back to the pair URLs within 5 minutes.
   - Rehearsed locally: correct on the first pass.
2. **Plugin, only after the API is back.** Rolling back the plugin first leaves the wrong-order row above.
   - Run:
     ```
     wp option update statchasers_news_installed_version 1.10.60
     ```
     Set this FIRST so no request runs a second sweep.
   - Reinstall the live zip (`ab0cc82d...`) or the step-0 backup:
     ```
     wp plugin install <zip> --force
     ```
   - Run step 3 again.
3. Purge as in step 5, then run the check again.

## Known limits

- **The game list only refreshes when Rank Math rebuilds a sitemap file.** Rank Math rebuilds after a post save, or when a file is missing from its cache. Weekly new games therefore reach the sitemap after the next post save once the 1 h list cache has expired. This predates WEB-001. A scheduled refresh would remove the lag and is not part of this release.
- **Every plugin version change sweeps the player and team caches**, as in 1.10.60, hence the warm in step 5. The cache-version plan in docs/WP-CACHE-RELIABILITY-1.10.60.md would decouple the two.
