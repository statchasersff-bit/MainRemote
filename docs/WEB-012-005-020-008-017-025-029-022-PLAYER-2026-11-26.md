### Root cause

All four were created by the 2026-09-20 17:56-17:58 build, the same run that made the 27 `-2/-3` pages trashed on
10-14. Two builders inserted the same row in the same instant. `wp_unique_post_slug()` is a SELECT before the INSERT,
not a constraint, so each insert saw the slug free and BOTH kept the bare slug. Nothing was renamed, so:
- the 10-14 post-insert rename check (which looks for a `-2`) cannot see this case, and
- the 10-14 cleanup, which searched for `-2/-3` slugs, missed them.
They did not recur: no lock-skipping path created them; they predate the lock (1.10.39, 10-14). The remaining lockless
creator is `wordpress-plugin/scripts/create-player-pages.sh` (WP-CLI), and a stale-lock takeover can still overlap a
slow holder. Both are now covered by the post-insert race settlement below.

### Fix (verified locally)

- `statchasers_player_create_page()` (new, used by the builder): insert, then the existing rename check, then
  `statchasers_player_settle_slug_race()`: read back every non-trash page at the slug under the container, oldest first;
  the oldest wins (the one `get_page_by_path()` serves). A process whose own new page is not the oldest force-deletes
  it and reports the winner. Every racer decides from the same ordering, so all agree on one page with or without the
  lock. It only ever deletes the page the process itself just created.
- `create-player-pages.sh`: the same post-insert read-back (rename -> delete ours, use the sibling; not oldest ->
  delete ours, return the oldest).
- Sitemap: `statchasers_player_sitemap_drop_left()` also drops a page shadowed by an older page at the same slug
  (`statchasers_player_post_is_shadowed`, from one memoized query); `statchasers_player_sitemap_sections()` lists the six
  tabs once per slug (posts come oldest first).
- Dry-run and apply tools: `statchasers_player_duplicate_plan()` (no writes) and
  `statchasers_player_duplicate_apply( $ids )` (trash only, only ids the CURRENT plan retires, never the keeper, never a
  retiree holding content/meta/old slug/thumbnail its keeper lacks).

one shared SQLite posts table whose `wp_insert_post` stub reproduces WordPress's non-atomic slug check (SELECT sibling

## 2. Game Log seasons (WEB-020)

### Finding (verified in production, read-only check)

The Gibbs hub printed six `<a href="/nfl/players/jahmyr-gibbs/?log=2023#game-log">`-style links (2023-2025, desktop chip
strip + phone menu). Matthew Stafford's Game Log has 18 seasons, so 34 such links. `?log=` pages returned 200 with a
clean canonical; the 11-20 audit measured 22% of Googlebot's player crawl on them, and each click fetched an uncached
WordPress render (FP-1).

### Fix (verified locally)

- Markup (`gamelog-premium.ts`): chips and phone-menu options are `<button type="button" data-season aria-pressed>`,
  in `role="group" aria-label="Game log season"`. No `href`, no `?log=` anywhere in the Game Log (0 on Gibbs and
  Stafford fragments, down from 6 and 34). The strip/menu carry `data-scp-log-default`, `data-scp-log-shown` and, when
  embedded, `data-scp-log-src` = the player fragment endpoint with this render's section/h1/format
  (`browserEndpoint`, i.e. `https://statchasers.com/wp-json/statchasers/v1/p/embed/player/<slug>?section=game-log&h1=1`
  in production).
- Client (`src/client/player.ts`): click -> fetch `log=<year>` from that endpoint (standalone: the page's own `?log=`),
  latest-wins (token + AbortController), swap the root, keep the open tab and focus, write `#log=<year>`
  (`replaceState`; removed for the default season). `#log=` is read on boot and on `hashchange`; a season the player
  has no log for is ignored and cleared.
- Plugin: `?log=` no longer feeds the render (one cached copy per URL); a `?log=YYYY` address 301s to
  `/game-log/#log=YYYY` (section 3). The proxy forwards `embed/player/<slug>` and now passes `h1` (keys may contain a
  digit after the first letter) so a swapped root keeps its H1.
- Caching: the page HTML no longer varies by season. The season variants live only on the fragment endpoint, keyed by
  the full URL in the proxy transient (`sc_proxy_` md5 of url incl. `log`), the API fragment LRU (`logSeason` in
  `optionKey`, plus the new `logEndpoint`) and the browser/CDN cache (`max-age=300`).
- Matchup FAQ links to past game logs use `game-log/#log=<season>` instead of `?log=`.
- CSS: a low-specificity button reset appended to `public/player.css`; Chromium screenshots at 1280 and 500 px show the
  chips and dropdown drawn as before.

Behavior evidence (verified locally): Chromium `--dump-dom` of `/player/jahmyr-gibbs/game-log/#log=2024` opens with
`data-scp-log-shown="2024"` and the 2024 chip lit; the bare URL opens on 2026. JSDOM tests in `tests/player.test.mjs`
(multi-season fixture): switching years re-renders in place, path unchanged, hash `#log=<year>`, focus kept, back to the
current season clears the hash; a bookmark reopens its season; `#log=1971` is ignored and cleared; two quick picks, the
later wins; the tab survives the swap; the embed fragment names the endpoint and the endpoint answers each season.

Without JavaScript the seasons are not selectable (the stats-audit precedent, WEB-020 on the Stats page, made the same
trade). The current season always renders.

## 3. URL normalization (WEB-008)

### Finding (verified in production, read-only check)

| Request | Live now |
|---|---|
| `/nfl/players/Jahmyr-Gibbs/` | 200, canonical lowercase |
| `/NFL/Players/jahmyr-gibbs/` | 200, canonical lowercase |
| `/nfl/players//jahmyr-gibbs/` | 200, canonical lowercase |
| `/nfl/players/jahmyr-gibbs` | 301 -> `/jahmyr-gibbs/` |
| `/nfl/players/jahmyr-gibbs/Stats/` | 404 |
| `/nfl/players/jahmyr-gibbs//stats/` | 301 -> `/stats/` |
| `/nfl/players/jahmyr-gibbs/game-log/?log=2024` | 200, canonical `/game-log/` |
| `/nfl/players/dandre-swift-2/` | 301 -> `/dandre-swift/` (Rank Math regex) |
| `/nfl/players/zz-not-a-player/`, `/jahmyr-gibbs/badtab/` | 404 |

### Fix (verified locally)

`statchasers_player_canonical_target()` + `template_redirect` priority 1 (before legacy 8, old-slug/overview 9 and
core's `redirect_canonical` 10): one 301 to the canonical profile or tab. Rules: lowercase, single slashes, trailing
slash; `/overview/` -> profile; a retired `-[2-9]` slug -> its published base; `?log=YYYY` -> `/game-log/#log=YYYY`
(other query parameters kept; an unreadable `log` dropped). Nothing is redirected unless the slug is a published
profile and the tab one of the sections, so unknown players and invalid tabs keep their 404, and the retired
`/nfl/players/<section>/<slug>/` layout stays with the legacy redirect.

Representative chains (unit-tested, 23 cases in `smoke-player-builder.php`):

| From | To (one hop) |
|---|---|
| `/nfl/players/Josh-Allen/` | 301 `/nfl/players/josh-allen/` |
| `/NFL/Players/josh-allen/` | 301 `/nfl/players/josh-allen/` |
| `/nfl/players//josh-allen/` | 301 `/nfl/players/josh-allen/` |
| `/nfl/players/josh-allen/Stats/` | 301 `/nfl/players/josh-allen/stats/` |
| `/nfl/players/josh-allen//game-log` | 301 `/nfl/players/josh-allen/game-log/` |
| `/nfl/players/josh-allen/overview/` | 301 `/nfl/players/josh-allen/` |
| `/nfl/players/josh-allen/?log=2024` | 301 `/nfl/players/josh-allen/game-log/#log=2024` |
| `/nfl/players/Josh-Allen/game-log/?log=2023&format=half` | 301 `/nfl/players/josh-allen/game-log/?format=half#log=2023` |
| `/nfl/players/josh-allen-2/news/` | 301 `/nfl/players/josh-allen/news/` |
| `/nfl/players/josh-allen/stats/` (canonical) | no redirect |
| `/nfl/players/Zach-Ertz-Unknown/`, `/josh-allen/badtab/`, `/josh-allen/stats/extra/` | no redirect (WordPress 404) |

Known two-hop case: `?log=` on a player with no Game Log section goes to `/game-log/`, which then 302s to the profile
(the existing missing-section rule).
