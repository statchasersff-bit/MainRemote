# WEB-033: game-log and upcoming matchup difficulty ranks (2026-11-26)

Branch `pa1126/i1`, base `main` 4cb49ac (code d7ebbe1, plugin 1.10.72). Nothing pushed, published or purged.

## Root cause

The 2026-11-25 audit's "FPA" figures are the FPA page's **Half-PPR** RB ranks, not PPR. The player
pages show PPR. The FPA page (`/nfl/fantasy-points-allowed-by-position/`) opens in Half-PPR
(`parseFpaFormat` default, `data-format="half"`), and every player-page link to it was the bare URL.

|---|---|---|---|---|
| NO | 3 | 3 | 3 | 3 (agreed) |
| BUF | 12 | 12 | 13 | 13 |
| NYJ | 8 | 8 | 6 | 6 |

All 11 audit "FPA" figures match the Half-PPR column exactly. All 11 game-log/strip figures match
the PPR column exactly. The in-page Scoring switch also works: the WP proxy
`/wp-json/statchasers/v1/p/embed/fpa?format=ppr` returns the PPR ranks. It changes the table
without changing the URL, though, so after a reload or a shared link the page is back on Half-PPR.

The other suspects were checked:
- **Position**: RB in both places.
- **Totals vs averages**: both use per-game. The FPA raw figure is the position's team total per
  game (`computeFpaTable`). The live table is the blend the ingest writes (90% 2026 / 10% 2025
  at Week 11). The game log and strip read that same table.
- **Cutoff**: the same snapshot.
- **Rank direction**: 1 = allows the most, everywhere.
- **Ties**: none in PPR RB. They were resolved in database row order (see the fixes).

**Why it "appeared fixed then returned".** Before f0b8e67 (11-19) the game log ranked defenses
with its own calculation (`buildOppRanks`, an average of single player lines). That was a real
disagreement (ARI 25th vs 13th). f0b8e67 switched the game log to the FPA table. The 11-20
verification (docs/REFERENCE-PAGES-2026-11-20.md) compared it against the PPR table and it
agreed. The 11-25 audit compared it against the page's default Half-PPR view. The ranking code
did not regress. The 11-20 doc already listed "FPA page defaults to Half-PPR" as open.

Two latent paths could also make the two pages disagree. Both are fixed below:
1. **Player-page cache key.** The render cache key held the upcoming opponents' ranks but not
   the FPA table version. An ingest that moved a past opponent's rank, but not the upcoming
   ones, could leave old Difficulty ranks in place.
2. **Separate 10-minute cache.** `matchupTable` answered from its own cache for 10 minutes after
   an ingest had already dropped the FPA memo.

## What each displayed rank means (after this change)

| Surface | Rank | Label the reader sees |
|---|---|---|
| Game Log Difficulty column (current season) | Today's live FPA rank (PPR raw, per game, position), the same table as the FPA page; the same for every row, not the rank entering that game | Note under the table: "Difficulty is each defense's current rank in PPR fantasy points allowed per game to RBs through Week 11, the same rank as the Fantasy Points Allowed page (PPR) ... today's rank for every row, not the rank entering that game." Cell tooltip uses the same words. |
| Per-week detail panel | Same figure | "NO ranks 3rd in PPR fantasy points allowed per game to RBs through Week 11 (current rank, not the rank entering this game)" |
| Upcoming Matchups strip (+ header chip, Outlook, FAQ, overview) | Same table (`matchupTable`) | "Matchup rank is fantasy points allowed per game to RBs, in PPR ... Measured through Week 11, the same ranks as the Difficulty column above." |
| `?log=2025` | FPA archive final rank, weeks 1-17 | "... in 2025 (Weeks 1-17), as on the Fantasy Points Allowed archive" |
| `?log=2024` and earlier (no FPA archive) | Same arithmetic over the stored game logs, full season | "... in 2024 (full season)" (the FPA page is not mentioned) |
| Current season, FPA table unreadable | **Unavailable**: dash, panel "Rank unavailable", note says so | No second calculation is used |

No historical row claims a pregame rank. A pregame view would need per-week FPA snapshots, which
are not stored, so per the brief the "current rank" meaning is kept and labeled.

## Changes

- `src/lib/fpa/math.ts`: `rankFpaValues()` is now the single ranking rule. Rank 1 = most allowed.
  Ties are broken by team code, so the order is deterministic.
- `src/lib/fpa/fpa-data.ts`: `rankRows` uses `rankFpaValues` (it replaces `rankDescending`, whose
  ties followed database row order). Today's ties are Half/Standard only (HOU/MIN TE half 7.93:
  unchanged; HOU/SEA TE std, NYJ/PIT WR std, CIN/PHI OFF half can swap one place).
- `src/lib/player/ranks.ts`: `buildOppRanks` (fallback for seasons before the archive) now uses
  the FPA arithmetic: position team totals per game the defense played, `rankFpaValues` ties.
  Against the 2025 FPA archive, mean absolute rank error is 1.36 (was 2.89), exact 34/128 (was 20).
  The remaining gap is the source (Sleeper logs vs nflverse). 2023/2024 fallback ranks change for
  ~105 of 128 team-position cells. New `OppRankSource` value "unavailable".
- `src/lib/player/player-data.ts`: the current season reads the FPA table or nothing. New
  `logOppRankThrough` (the table's cutoff label) and `fpaStamp` (the version of every FPA table
  read) go into `playerDataVersion`.
- `src/lib/player/upcoming.ts`: `matchupTable` reads through `getFpaTable`'s memo, which every
  ingest drops. Its own cache is only a fallback, with a 60 s retry backoff after a failed read.
- `src/lib/fpa/matchup-bands.ts`: `oppRankScope()` (shared wording) and `fpaFormatHref()`.
- `src/lib/player/gamelog-premium.ts`, `src/lib/player-render.ts`,
  `src/lib/player/breakdown-premium.ts`: the labels above. FPA links carry `?format=ppr`
  (`&format=ppr` after `?embed=1`).
- `src/lib/matchup/matchup-render.ts`: comment only.
- Tests: new `tests/web-033-opp-ranks.test.mjs` (6) covers:
  - unequal games played (AAA 2 g / BBB 3 g / CCC committee), where per game, totals and
    per-line averages give three different orders;
  - `computeFpaTable` divides by games;
  - tie rule;
  - wording;
  - unavailable state;
  - format link.

  `tests/player.test.mjs` updates: the caption href is now `/fpa?format=ppr`, and the stale
  10/23 band cut in the Difficulty test is now 12/21.
